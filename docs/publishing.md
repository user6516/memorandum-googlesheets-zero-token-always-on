# 发布到 GitHub

本文件夹是可独立管理的本地 Git 项目。GitHub 远程仓库需要由维护者另外创建并上传；本项目不会自动操作 Google 账号或发布内容。

## 发布前

1. 保持 `src/Code.gs` 中的 `recipient` 为 `YOUR_EMAIL_HERE`。实际部署时在自己的在线脚本中填写邮箱。
2. 运行 `npm run check`，检查测试与基础敏感信息扫描结果。
3. 查看 `git status` 和待提交差异，确认不包含个人任务、真实邮箱、私有表格链接、脚本绑定标识、账号截图或授权文件。
4. 在本机设置适当的 Git 提交作者。希望隐藏个人邮箱时，可使用 GitHub 设置提供的隐私提交邮箱。
5. 按实际分发意图选择并添加 `LICENSE`，本模板没有替维护者选择许可。

`.gitignore` 排除了常见的本地凭据、账号绑定文件、日志、私人导出和截图目录。扫描只覆盖常见模式，不能替代提交前人工审查，也不能自动清除已经提交到历史中的信息。

## 网页上传

在 GitHub 新建空仓库，使用“上传文件”上传本项目内容。隐藏文件需确认一并上传；上传完成后，Actions 会运行测试与隐私检查。

## 使用 Git

本地目录已初始化为 `main` 分支。完成提交作者设置后，在项目目录执行：

```bash
git add .
git diff --cached
git commit -m "Initial project scaffold"
```

在 GitHub 创建空仓库，按该页面提供的命令配置远程地址并推送。避免在远程 URL 中嵌入访问令牌。

## 部署与源码分开

上传仓库不等于已安装云端提醒。其他使用者需要在自己的 Google 表格中复制程序并运行 `setup` 完成授权。表格数据、Script Properties、邮件和触发器不会随源码转移。

`src/appsscript.json` 提供 V8 和北京时间的清单示例；手动复制 Code.gs 的安装方式只需按教程设置项目时区，无需额外部署 Web 应用。
